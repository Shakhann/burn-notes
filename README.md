# 🔥 Бір реттік қорғалған жазбалар (burn-notes)

Privnote-қа ұқсас веб-қосымша: мәтін **браузерде AES-256-GCM** шифрланады,
серверде тек шифрланған деректер сақталады, ал жазба **бірінші рет ашылған
сәтте толығымен жойылады**.

## Бір сайт, екі таб

Сайтқа кіргенде үстінде екі тапшымала (таб) болған бір бет ашылады:

| Таб | Қызметі |
|---|---|
| 🔥 **Жазба жасау** | Мәтін + мерзім (1 сағ / 24 сағ / 7 күн / тек 1 рет) + ерікті құпия сөз → бірегей сілтеме |
| 👁 **Жазба оқу** | Кұпия сілтемені жапсырып «Оқу» батырмасын басу — немесе сілтемені тікелей ашу |

`/note/<id>#<кілт>` сілтемесін ашқанда бет **өзін-өзі «Жазба оқу» табына
ауыстырып**, жазбаны дайындайды (құпия сөзбен қорғалған болса — құпия сөзді
сұрайды).

## E2EE қалай жұмыс істейді

1. **Жіберуші** (таб «Жазба жасау») браузерде кездейсоқ AES-256 кілті
   генерациялайды (`crypto.subtle.generateKey`).
2. Мәтін шифрланады: `payload = base64url( IV(12 байт) || ciphertext )`.
3. Кілт URL-дің **hash** бөлігіне жасырылады:
   - құпия сөзсіз: `#k=<base64url(кілт)>`
   - құпия сөзі бар: кілт PBKDF2-кілтімен «оралып»,
     `#k=<wrapped>&s=<salt>&pw=1` — құпия сөздің өзі ешқандай жерде жүрмейді.
4. Серверге тек `POST /api/notes { data: payload, ttl }` келеді — браузер
   `#fragment`-ті серверге жібермейді, сондықтан **кілт серверге жетпейді**.
5. **Алушы** (таб «Жазба оқу») кілті URL-ден алып, ciphertext браузерде
   дешифрлайды. Сервер ашық мәтінді ешқашан көрмейді.
6. `GET /api/notes/:id` атомдық «оқу + өшіру» жасайды — екінші сұрау 404.
   Ашылмаса — TTL бойынша автоматты өшеді.

## Қауіпсіздік

- **Кілт** URL hash-інде → серверге кетпейді.
- **Логтар**: тек id / ttl / статус логталады; request body (ciphertext)
  пен кілт логқа түспейді.
- **Тілбастар**: `Referrer-Policy: no-referrer` (кілт Referrer арқылы
  үшінші тарапқа ағылмайды), `Cache-Control: no-store`,
  `X-Content-Type-Options: nosniff`.
- Кілт жазба ашылып болған соң **URL-ден тасталады** (`history.replaceState`).
- **id** = `crypto.randomBytes(16)` (128 бит) — болжау мүмкін емес.
- Барлық 404-тер бірдей — жазба «ашылған / мерзімі өткен / жоқ» айырмасын
  сырттан білуге болмайды.
- Қате құпия сөзде серверге сұрау түспейді → жазба жойылмайды.

## Қосымша мүмкіндіктер

- **QR-код**: сілтеме QR-ретінде шығады — алушы телефонмен сканерлеп ашады
  (кілт сілтемеде ғана, E2EE бұзылмайды). QRCode.js (CDN).
- **Бөлісу батырмалары**: WhatsApp, Telegram және жүйелік «Бөлісу…»
  (`navigator.share` болса) — толық сілтемені бір басымента жіберу.
- **«Менің жазбаларым»**: жіберілген сілтемелердің жергілікті тізімі
  (localStorage, серверде емес). Әр жазбаның жағдайы автоматты жаңарады:
  жасыл нүкте — әлі оқылмады, қызғылт — оқылды/мерзімі өтті.
  Жағдай `GET /api/notes/:id/status` (оқу емес, жазба жойылмайды) арқылы
  сұралады; id 128 бит кездейсоқ болғандықтан бұл oracle емес.
- **Drag & drop**: файлдарды аймаққа тікелей тастауға болады.
- **Ашылған жазбада**: мәтінді көшіру + `.txt` ретінде жүктеу батырмалары.

## Production: Redis (TTL + GETDEL)

`npm i redis` қосып, `store.js`-тегі логиканы мынадай нұсқаға ауыстырыңыз:

```js
const { createClient } = require('redis');
const client = createClient({ url: process.env.REDIS_URL || 'redis://localhost:6379' });
await client.connect();

function storeSet(id, data, ttl) {
  const key = `note:${id}`;
  if (ttl > 0) client.set(key, data, { EX: ttl }); // Redis өзінде TTL-мен өшіреді
  else client.set(key, data);
}
async function storeConsume(id) {
  return (await client.getDel(`note:${id}`)) ?? null; // атомдық оқу+өшіру (Redis >= 6.2)
}
```

Ескі Redis үшін `GETDEL` орнына Lua-скрипт:
`local v = redis.call('GET', KEYS[1]); if v then redis.call('DEL', KEYS[1]) end; return v`.

## Шектеулер / келесі қадамдар

- In-memory сақтау: сервер қайта іске қосылса, ашылмаған жазбалар жоғалады
  → production үшін Redis.
- `express-rate-limit`, WAF — production үшін.
- **HTTPS** (nginx/caddy reverse proxy) — `crypto.subtle` тек secure
  context-те (https немесе localhost) жұмыс істейді.
- Tailwind/Lucide CDN арқылы жүктеледі (интернет керек); offline үшін
  Tailwind CLI build жасау керек.
